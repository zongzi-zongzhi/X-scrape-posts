# PRD

## 1. 需求背景

InsForge 需要从 X 公开帖子中持续发现潜在线索：这些人正在用 AI 工具构建 App、网站、SaaS、MVP 或独立开发项目，但在后端、数据库、登录注册、权限、RLS、Auth、API Key、部署、环境变量或数据保存环节遇到问题，或者明确表达这些配置工作繁琐、不想手动处理。

过去的手工筛选效率低，且容易混入教程、资讯、热榜、招聘、课程、社群、开源项目推荐或 InsForge 自己人相关内容。因此需要一个本地可控、只读、安全、可审计的自动化程序。

## 2. 项目目标

- 每天按语言抓取 X 公开帖子线索。
- 严格按目标画像、语言和排除规则筛选。
- 写入固定飞书多维表前完成字段检查、重复检查和 dry-run。
- 保留完整运行产物，便于复查和纠错。
- 不执行任何 X 互动动作。

## 3. 目标用户

- InsForge 增长、产品和运营人员。
- 负责 X 线索发现、建联和质量复盘的内部成员。
- 后续维护该自动化的工程人员。

## 4. 用户场景

- 每天早上自动跑一次，生成当日新增线索。
- 用户在飞书中查看候选帖子质量，并人工决定是否回复。
- 发现误入库后，用户要求删除记录、撤回去重状态并补充过滤规则。
- X 或飞书凭据失效时，用户需要明确知道卡在哪一步。

## 5. 用户故事

| 编号 | 用户故事 | 优先级 | 验收标准 |
|---|---|---|---|
| US-001 | 作为增长人员，我希望每天自动获得 X 建联线索，以便减少手动搜索成本。 | P0 | Given 凭据有效，When 执行每日脚本，Then 生成日报并按规则写入飞书。 |
| US-002 | 作为运营人员，我希望候选帖子严格匹配语言和画像，以便飞书表不被低质量内容污染。 | P0 | Given 帖子为教程、招聘、热榜或语言不匹配，When 过滤执行，Then 该帖进入 rejected。 |
| US-003 | 作为维护者，我希望同步前读取飞书已有链接和“不需要回”样本，以便避免重复和动态排除低质量模式。 | P0 | Given 飞书 CLI 可用，When 同步脚本运行，Then sync report 包含字段、已有记录和 no-reply profile。 |
| US-004 | 作为维护者，我希望凭据失效时程序明确失败点，以便快速恢复授权。 | P0 | Given X 或飞书凭据不可用，When 运行脚本，Then 输出清晰错误并不伪造数据。 |
| US-005 | 作为负责人，我希望每日每种语言入库 10-25 条，以便保持稳定线索供给。 | P1 | Given fresh 少于 10 条，When append 请求执行，Then sync report 写入 blocked_reason 且不 append。 |

## 6. 输入内容

- X 搜索关键词配置。
- 语言过滤配置。
- 排除关键词与画像规则。
- 本地 X provider 凭据引用。
- 飞书 base token、table id 和 lark-cli profile。
- 本地 seen state 和 no-reply 样本。

## 7. 输出结果

- 原始帖子 JSONL。
- 过滤后候选 JSON。
- 可读 Markdown 候选报告。
- run log。
- 飞书 sync report。
- daily report。
- pointer 文件。

## 8. 核心功能

| 编号 | 功能 | 说明 | 优先级 | 验收标准 |
|---|---|---|---|---|
| FR-001 | 只读 X 采集 | 从 provider 搜索公开帖子，不执行互动动作。 | P0 | 代码中 provider 仅暴露 read-only search。 |
| FR-002 | 语言过滤 | 简中、繁中、英、日、韩分别校验正文脚本。 | P0 | 语言不匹配进入 rejected。 |
| FR-003 | 画像筛选 | 必须命中项目场景、后端痛点、求助或吐槽意图。 | P0 | 不符合画像进入 rejected。 |
| FR-004 | 禁用 InsForge 内容 | 搜索、匹配、候选正文都不得包含 InsForge。 | P0 | 包含 insforge 的正文进入 rejected。 |
| FR-005 | 飞书 dry-run | 读取字段、已有记录和 no-reply 样本后生成 dry-run 报告。 | P0 | append 前存在 sync_report。 |
| FR-006 | 数量门禁 | 每种语言每天 10-25 条。 | P1 | fresh 少于 10 时阻止 append；超过 25 时截断。 |
| FR-007 | 本地去重 | 基于 URL、post id、作者与正文 hash 去重。 | P0 | 重复内容不写入。 |
| FR-008 | 审计输出 | 保留 raw、leads、log、sync、daily report。 | P0 | 每次运行输出路径可追踪。 |

## 9. MVP 范围

- 本地命令行运行。
- 支持 X 公开帖子采集。
- 支持简中、繁中每日自动化。
- 支持英、日、韩多语言脚本。
- 支持飞书 CLI 同步。
- 支持 dry-run-first 和数量门禁。

## 10. 非目标范围

- 不做 X 互动。
- 不做账号池管理。
- 不做密码登录、验证码绕过或批量账号操作。
- 不做网页 SaaS。
- 不自动填写人工评论字段。

## 11. 业务规则

- X 侧只读。
- 飞书侧只追加，不覆盖旧记录。
- 人工字段必须留空。
- 凭据缺失或失效必须明确报错。
- 每种语言独立计算数量。
- 每种语言每天最多写入 25 条。
- 每种语言 fresh 少于 10 条时阻止 append，并记录 blocked_reason。

## 12. 数据与权限边界

- 真实 `.env`、Cookie、token、provider DB 和 outputs 不应提交。
- 飞书授权使用本地 lark-cli profile。
- 输出目录用于审计和本地排错，不作为公开数据集。

## 13. 风险与待确认事项

- X provider 的稳定性取决于账号、Cookie、官方 API 权限和平台限流。
- 规则筛选可能误伤或漏放，需要持续根据飞书反馈迭代。
- 当前没有人工审核 UI，误入库修复依赖脚本和维护者操作。

## 14. 成功标准

- 本地测试通过。
- dry-run 能生成完整报告。
- append 被数量门禁和字段检查保护。
- 误入库记录可追溯、可删除、可补规则。
- 新维护者能通过 README 和 docs 理解项目并运行 demo。
